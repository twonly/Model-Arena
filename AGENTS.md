## Model evaluation and publication

For new creative evaluations, follow [`docs/model-evaluation.md`](docs/model-evaluation.md)
and [`docs/evaluation-suite-v6.md`](docs/evaluation-suite-v6.md). The default is
`--profile creator` / `creative-suite-v6`: an exploded Blender handheld console,
a Web3D underwater laundromat, a three-operation web app, a data chart, and a
two-image spot-the-difference task. `standard`, `quick`, and `extended` explicitly retain
v4; historical batches and successful artifacts keep their original protocol.
Only selected knowledge-video tasks need the v4 date-locked topics and narration
workflow. Do not automatically add retired tasks or thinking-mode comparisons.

The tested model makes the work. Allow autonomous self-checking, then freeze its
first autonomous delivery, source and hashes, including failures and missing
items. Coordinator feedback and subsequent repairs are separate labeled versions;
never overwrite or present them as the first delivery. Keep persistent sessions
and use backoff for provider outages; historical request/token/time caps do not
apply, and perfect scores are not a completion requirement.

Run the necessary technical and factual checks and inspect actual artifacts.
AI notes are limited to three verifiable facts or key omissions per case, with
screenshots or timecodes. No default subjective scores, overall rankings or
engineering essays. Leave the blogger commentary pending until the user supplies
opinions, then polish those opinions without inventing evidence. State the model,
harness and actual tools; comparisons of native products concern the whole system.

New tasks default to local drafts. Existing authorization remains valid only for
the task it covers. Publish when explicitly requested for that task, using the
existing bilingual, asset/hash, build and canonical production verification flow.
